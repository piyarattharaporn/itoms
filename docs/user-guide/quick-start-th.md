# ITOMS Quick Start ภาษาไทย

คู่มือนี้ช่วยให้ผู้ใช้ใหม่เริ่มทำงานกับ IT Outsource Managed System ได้ภายในไม่กี่นาที โดยเน้นงานที่ต้องทำบ่อยที่สุด: เข้าระบบ เลือก Property สร้างหรือรับงาน อัปเดตสถานะ และอ่านภาพรวม

## 1. ก่อนเริ่มใช้งาน

ผู้ใช้ต้องมีบัญชี Firebase Authentication และต้องมี Profile ที่เปิดใช้งานพร้อมสิทธิ์ใน Property อย่างน้อยหนึ่งรายการ หากเข้าสู่ระบบได้แต่เห็นข้อความว่าไม่มี Profile หรือไม่มี Property ให้ติดต่อ Super Admin

ระบบรองรับ:

- Email และ Password
- Google Sign-In เมื่อผู้ดูแลเปิด Provider และกำหนด Authorized Domain แล้ว

## 2. เข้าระบบและตรวจสอบขอบเขต

1. เปิดระบบ ITOMS
2. เข้าสู่ระบบด้วย Email/Password หรือ Google
3. ตรวจสอบชื่อและรูปผู้ใช้ที่มุมขวาบน
4. เปิดเมนูผู้ใช้เพื่อตรวจสอบ Role และ Property ที่เข้าถึงได้
5. เลือก Property จากตัวเลือกด้านบนก่อนอ่านข้อมูลหรือบันทึกรายการ

Super Admin จะเห็นตัวเลือก `ทุก Property` ส่วนผู้ใช้ทั่วไปจะเห็นเฉพาะ Property ที่มี Membership และสถานะ Active

## 3. สร้าง Task

ผู้แจ้งงานหรือผู้ที่มีสิทธิ์สร้างงานเลือกเมนู `Create Task` แล้วกรอกข้อมูลตามลำดับ:

1. Property และช่องทางการแจ้งปัญหา
2. ผู้แจ้งงานหรือผู้แจ้งแทน
3. พื้นที่หรือกลุ่มปัญหา และความสำคัญ
4. หมวดปัญหา ประเภทย่อย ห้องหรือพื้นที่ และแผนก
5. Asset ที่เกี่ยวข้อง ถ้ามี
6. รายละเอียดอาการหรือผลกระทบ
7. ตรวจสอบข้อมูล แล้วกด `สร้าง Task`

Task ใหม่จะเริ่มที่สถานะ `Pending` และใช้รหัสที่ระบบสร้างให้ ห้ามสร้างรหัสเองเพื่อป้องกันรหัสซ้ำ

## 4. รับงานและอัปเดตสถานะ

เปิดเมนู `กระดานงาน` หรือ `Task Board` เพื่อค้นหาและติดตามงาน ผู้ดูแลหรือ Support Engineer สามารถ:

- ค้นหาด้วยรหัส หัวข้อ สถานที่ หรือรายละเอียด
- กรองตามสถานะ
- ดูแบบตารางหรือ Kanban
- มอบหมายงานให้ Support Engineer
- เปลี่ยนสถานะ
- เปิดรายละเอียดเพื่อแก้ไขข้อมูลปฏิบัติงานตามสิทธิ์

สถานะที่ใช้บ่อย:

| สถานะ              | ใช้เมื่อ                              |
| ------------------ | ------------------------------------- |
| Pending            | รับแจ้งแล้วแต่ยังไม่เริ่มดำเนินการ    |
| In Progress        | กำลังตรวจสอบหรือแก้ไข                 |
| Monitoring         | แก้ไขแล้วและกำลังเฝ้าดูผล             |
| Waiting for Vendor | รอ Vendor หรือผู้ให้บริการภายนอก      |
| Waiting for User   | รอข้อมูลหรือการยืนยันจากผู้แจ้ง       |
| Completed          | แก้ไขและยืนยันผลเรียบร้อย             |
| Cancelled          | ยกเลิกอย่างมีเหตุผลและไม่ดำเนินการต่อ |

## 5. ปิดงานอย่างถูกต้อง

ก่อนเปลี่ยนสถานะเป็น `Completed` ต้องกรอกวิธีแก้ไขอย่างน้อย 10 ตัวอักษร และไม่เกิน 4,000 ตัวอักษร ควรเขียนให้ตอบได้ว่า:

- พบสาเหตุอะไร
- ดำเนินการอะไร
- ตรวจสอบผลอย่างไร
- มีสิ่งที่ต้องติดตามต่อหรือไม่

ระบบจะบันทึก `completedAt` ตอนเปลี่ยนเป็น Completed และใช้เวลาตั้งแต่ `createdAt` ถึง `completedAt` เป็นเวลาแก้ไขเฉลี่ยในรายงานที่เกี่ยวข้อง

## 6. อ่าน Dashboard อย่างรวดเร็ว

หน้า `ภาพรวม` ใช้ตรวจสุขภาพงานในขอบเขต Property ที่เลือก:

- KPI แถวบน: เลยกำหนด ใกล้ครบกำหนด Critical งานที่ยังเปิด และ Response SLA
- `งานที่ยังไม่เสร็จ`: งานที่ยังไม่เป็น Completed หรือ Cancelled จากรายการที่โหลด เรียง SLA ก่อน
- Badge ในรายการ: แยกสถานะ SLA ออกจากสถานะ Workflow ของ Task
- `บันทึกเหตุขัดข้อง`: ดู Incident ที่ยังไม่กู้คืนหรือมีผลกระทบสูง
- `ติดตาม SLA`: ดูภาพรวม Response และ Resolution ตามข้อมูลที่โหลด

การ์ดงานเปิดจะแสดงรายการแรก ๆ เพื่อให้หน้าอ่านง่าย หากมีงานมากกว่าที่แสดง ให้กด `ดูรายการทั้งหมด`

## 7. กรณีอุปกรณ์เสีย

เปิด `อุปกรณ์เสียหาย` เพื่อดู Asset ที่มี Label สถานะ:

- `Damaged` หรือ เสีย
- `Under Repair` หรือ กำลังซ่อม
- `Retired` หรือ เลิกใช้งาน

หากต้องการเปลี่ยนข้อมูล Asset ให้ไปที่ `อุปกรณ์และลิขสิทธิ์` ผู้ใช้ที่ไม่มีสิทธิ์จัดการจะดูได้ตามขอบเขตที่ได้รับอนุญาตเท่านั้น

## 8. สิ่งที่ควรทำทุกครั้ง

- ตรวจ Property และช่วงเวลาก่อนอ่านตัวเลข
- ใช้ displayName ของผู้รับผิดชอบในการสื่อสารกับทีม
- เขียนรายละเอียดและวิธีแก้ไขให้ผู้อื่นทำตามได้
- เปลี่ยนสถานะให้ตรงกับความคืบหน้าจริง
- ใช้ Export หลังตรวจสอบจำนวนข้อมูลที่โหลดแล้ว
- หากพบข้อมูลผิด ให้ใช้ Controlled Edit พร้อมเหตุผล แทนการลบรายการ
